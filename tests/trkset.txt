# ---- PROG and CHANNEL state the program on the wire, stopped or not ----
#
# The tick path sends PC only while the transport runs (owner + sent_prog), and
# a stopped transport returns before that block - so on this page the PROG row
# changed the track and the synth never heard it: the keys auditioned the OLD
# voice. John 2026-10-30: "track set的program change的时候，是不是没有发送PC，
# 那么弹奏试听就无用了". A detent now sends, from the edit itself.
tap ENV
wait 20
expect mode 4
turn K1 1
wait 10
expect ts_row 1                       # PROGRAM
out
turn K2 1
wait 10
expect_out USB B9 00 78              # CC0 = 120 on the drum channel: a kits
expect_out USB B9 20 00              #   change needs bank select
expect_out USB C9 01 00              # the demo's bass is ch10 (0xC9): one detent up from 38 is 39 -> 0x01
out
turn K2 -1
wait 10
expect_out USB B9 00 78
expect_out USB C9 00 00              # and back: 38 -> 0x00
out
# the same for the channel: a program belongs to the channel it moved to
turn K1 -1
wait 10
expect ts_row 0                       # CHANNEL
turn K2 1
wait 10
expect_out USB CA 00 00              # ch10 -> ch11, and program 38 stated there
out
turn K2 -1
wait 10
# back on ch10: nothing goes out, and that is right. The receiver's copy of ch10
# is still program 38 in bank 120 (sent above); ch11's copy is the one that
# changed. sent_prog[] is per channel for exactly this reason — a channel walked
# away from and back to holds the same program, so re-stating it would be a
# message about nothing. (This pair used to say "expect_out ... C9 00 00" and
# only passed because the old `#` continuation aborted the file before it.)
expect_no_out USB B9 00 78
expect_no_out USB C9 00 00
out
tap HOME
wait 20
expect mode 0
