# Header — 设计稿 v1

对象：HOME / GRID(mel) / GRID(drum) / EDIT / ARP 的顶栏。
约束：240×224 画布（HOME 用满，GRID-drum 只有 160），FONT_T = 12px line / 8px cap，
1px 是能画的最小结构线，RAM 只剩 3,868 B。

---

## 0. 先修的问题：现在没有 header，只有五条不一样的 bar

实测（同一构建，翻页后逐页量右侧边缘的连续背景高度）：

| 页面 | bar 高 | 字形 y |
|---|---|---|
| HOME | 20 px | 6..13 |
| GRID mel | 16 px | 4..11 |
| GRID drum | 16 px | 4..11 |
| ARP | 16 px（+下方同色，量到 28） | 6..27 |
| EDIT | 16 px（同 ARP） | 6..27 |

翻页时 bar 高度差 4px、文字跳 2px。眼睛把这读成"整块屏幕在抖"，
比缺位图严重得多。**统一成一条 20px 的 bar，文字统一 y=6。**

为什么是 20 而不是 16：FONT_T 的 8px 大写高在 16px 里上下各剩 4px，
挤得两个元素互相贴住；20px 给到 6px 呼吸，而且 HOME 已经是 20。

## 1. 结构：三栏，槽位固定

```
x=0                                                              239
┌──────────────────────────────────────────────────────────────────────┐ y=0
│ ▮ TRACK   1        │  1 BAR  │  16 STEPS  │  120 BPM  │  ● S1      │
└──────────────────────────────────────────────────────────────────────┘ y=19
  └─轨色标记 8px       └─轴─┘    └──网格──┘   └──时钟──┘  └─loop 起点─┘
       ↑ 144px 单一语境区（轨道身份）        ↑ 右侧 4 个等宽读数格
```

三条规则：

1. **左端轨色标记**——8×8 的实心方块，颜色取 `TRACK_HUE(sel_track)`。
   它承担的是"这一屏在编辑哪一轨"，而颜色是全 UI 里已用于轨道的唯一标识。
   没有它，翻到 GRID 就只能靠"TRK 3"这段文字来认轨。
2. **中区是一句话，不是四段字**——`TRACK 1` 是身份，右边的
   `1 BAR / 16 STEPS / 120 BPM / S1` 是四个**读数**。
   现在它们散落在 x=6、96、168、204，中间 x=102..167 有 66px 空洞，
   每个数字都像失物。改成右对齐的四个等宽格，每格之间 1px 竖线（色 `#2a2a34`）。
3. **格宽按内容固定，不按页变**——`1 BAR` 和 `16 STEPS` 在不同页出现，
   必须落在同一 x。这正是现在 `div_str` 在 x=96（GRID）和 x=168（HOME）两处的毛病。

槽位（x 为左边缘）：

| 槽 | x | 宽 | 内容 | 颜色 |
|---|---|---|---|---|
| 轨色块 | 5 | 8 | `cv_rect(5,6,8,8,hue)` | `TRACK_HUE` |
| 身份 | 17 | 76 | `TRACK 1`（FONT_T 大写） | `TB_TX` |
| 分隔 | 94 | 1 | `cv_rect(94,4,1,12,SEP)` | `#2a2a34` |
| 轴 | 98 | 46 | `1 BAR` / `4 BAR` | `#7a7a88` |
| 分隔 | 145 | 1 | 同上 | |
| 网格 | 149 | 52 | `16 STEPS` / `8 STEPS` | `#7a7a88` |
| 时钟 | 205 | 24 | `120`（BPM，右侧留白给单位） | `TB_TX` |
| loop | 232 | 6 | `S1` 或 `●`（mute） | `GREEN_OK` / `MUTE_GRAY` |

## 2. 位图：只放两处，且必须有语义

你说"位图肯定还是需要的"。同意，但**每一位图都要能回答"它承载什么信息"**——
参考图里那个亮黄 `PROPHET` 块之所以成立，是因为它是音源名；四个小点是翻页指示。

本屏可用的位图只有两类，因为它们各自对应一个别的元素答不出的问题：

### (a) 轨型字形 8×8，画在 x=5 的位置、替换轨色块的下半

`TRACK` 这个词不区分鼓和旋律，但屏幕内容完全不同。

```
鼓：  ████     旋律：  ▂▄█▄▂
      ████             (柱状)
```

成本：2 个字形 × 8 B = 16 B（1bpp，8×8）。位置：x=5, y=11，与轨色块同列。

### (b) 翻页指示 3×3 点阵，右下角 x=232..238

5 个页面（HOME/GRID/EDIT/ARP + 鼓&旋律两种 GRID）→ 最多 5 点，当前页实心。
这一位图必须存在，因为**顶栏不放模式名**（你的反冗余原则：屏内容自明）。
但"我在第几页"是个不能自明的属性——5 个页面之间没有顺序感。

```
● ○ ○ ○ ○     当前 HOME
○ ● ○ ○ ○     当前 GRID
```

成本：0 B——`cv_rect` 画 5 个 3×3 方块，实心/空心各一种颜色。
做成位图反而更贵（5 个字形 15 B），而且这形状简单到不该占 flash。

**所以真正要新增的位图只有 (a)：16 B。**

## 3. 不做的事

- **不放模式名**（`HOME`/`GRID`）——屏内容自明，你的原则。
- **不放音量/波形/示波器**——参考图有，但那属于另一个产品的问题。
- **不做圆角与 1px 描边**——参考图有 4px 圆角和 1px 边，那是 2× 分辨率下的产物；
  240px 宽、1px 是唯一结构线，圆角只会把 8×8 的角吃掉两个像素。
- **不做顶部 4px 彩条**——参考图那条是产品色带，本机没有"全局产品色"这个概念；
  如果要做，只能是当前轨色，而那已经由左端色块承担。

## 4. 代价

### 高度预算：24px 是上限，靠鼓页 lane 间距换来的

四个页面的高度预算都算过（`/tmp/budget.mjs` 可复现）：

- **HOME**（16 行 × 12px 间距）：header 上限 **24px**（28 就溢出 footer）
- **ARP/EDIT**（圆环顶固定在 y=32）：header 上限 **32px**
- **GRID drum**（9 lane + 卡片必须从 y=115 起）：**这是唯一卡死的页面**

鼓页现状：`lh=11` → `9×11 = 99px`，`y0=16` 恰好吃满到 115。
header 要 24px，就得把 lane 压到 `lh=10` → `90px`，`y0=24` 到 114，正好。

关键是 `lh` 从 11 降到 10 **不会缩小方块**：
`cellh = lh - gap`，现在 `11-4 = 7`；改成 `lh=10, gap=3` 后 `10-3 = 7`，**方块仍是 7px**。
变化的只是行间距 4→3px。9 行共省 9px，header 拿 8px。

> 这是本方案唯一动到既有画面的地方，且只动鼓页的 1px 行距。
> 若你不同意，header 只能停在 16px，或接受鼓页例外。

### 其余代价

- RAM：两个 8×8 字形共 16 B，在 flash（`const`），RAM 影响 0。
- 每帧：多 2 个 `cv_rect` + 2 个 8×8 位图（64 次 `cv_pset`），可忽略。
- `ui_probe` 里"HOME 16 行"和"y214 有内容"的断言需要同步更新。

## 5. 已定

**全部确认（John，2026-10-26）：**
- **header 24px**，鼓页 lane 改 `lh=10 / gap=3`（方块仍 7px）。
- **轨型字形**：画。鼓=实心块，旋律=轮廓柱形。8×8，16 B flash。
- **`16 STEPS` 槽位**：drum 页留空，横轴一页 16 列本来自明。
- **第二行同槽位不同内容**：鼓页读当前鼓名（`KICK`/`SNARE`），旋律页读
  `4 BAR · 16 STEPS`。两者读的都是"这一屏在看什么"，语义一致。
